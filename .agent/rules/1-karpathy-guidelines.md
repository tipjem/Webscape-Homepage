# 안드레이 카파시 코딩 원칙 (Karpathy Guidelines)

이 규칙은 AI가 코드를 작성하거나 수정할 때 발생하기 쉬운 흔한 실수(과도한 추상화, 불필요한 기능 추가 등)를 방지하기 위한 불변의 행동 지침입니다.

---

## 1. 코딩 전에 먼저 생각하기 (Think Before Coding)
- **가정을 명시하세요**: 확실하지 않은 사항은 임의로 넘겨짚지 말고 사용자에게 질문하세요.
- **여러 해석이 가능할 때**: 혼자 임의로 선택하지 말고 대안들을 사용자에게 제시하세요.
- **더 단순한 방법이 있다면**: 솔직하게 말하고 더 간단하고 직관적인 방향을 제안하세요.
- **모호한 부분이 있다면**: 구현을 멈추고 헷갈리는 부분을 명확히 질문하세요.

## 2. 단순성 최우선 (Simplicity First)
- **요청받은 최소한의 코드만 작성**: 요청받지 않은 기능, 불필요한 확장성, 단 1회용 코드에 대한 복잡한 추상화를 만들지 마세요.
- **불필요한 에러 처리 금지**: 실제 발생할 수 없는 불가능한 시나리오에 대한 과도한 예외 처리를 지양하세요.
- **간결함 추구**: 50줄로 끝낼 수 있는 작업을 200줄로 늘려 쓰지 마세요. 시니어 엔지니어가 보았을 때 "지나치게 복잡하다"고 느낀다면 즉시 단순화하세요.

## 3. 외과수술적 최소 수정 (Surgical Changes)
- **손대야 할 곳만 정확히 수정**: 건드릴 필요가 없는 인접 코드, 주석, 기존 포맷팅을 임의로 건드리지 마세요.
- **고장 나지 않은 것을 리팩토링하지 마세요**: 기존 스타일을 존중하고 유지하세요.
- **내가 만든 찌꺼기만 정리**: 내 수정으로 인해 사용되지 않게 된 import나 변수는 깔끔하게 지우되, 기존부터 있던 코드는 요청받지 않는 한 지우지 마세요.
- **원칙**: 변경된 모든 코드 라인은 사용자의 요구사항과 직접 연결되어 있어야 합니다.

## 4. 목표 기반 실행 (Goal-Driven Execution)
- 검증 가능한 명확한 목표를 세우고 검증될 때까지 루프를 수행하세요.
- 단순히 "작동하게 만든다"가 아니라, 구체적인 검증 기준(예: "모바일 너비에서 가로 스크롤이 없는지 확인", "명도 대비 4.5:1 통과 확인")을 충족해야 작업을 완료로 처리합니다.
